## 한 줄 요약

**이론적으로 최적인 경로를 계산해 학습시켜 시뮬레이터 1위(7.473초)를 만들었지만,

## 최종 채택 모델

**`D-speedup-clone`** — [콘솔](https://d3da4vts8hz3fj.cloudfront.net/models/r58VqnOQYgCIgy7)

| 항목 | 값 |
| :--- | :--- |
| 트랙 | A to Z Speedway · **Counterclockwise** |
| 보상 함수 | 중앙선 추종 + 조향 변화율 페널티. **좌표 없음** |
| 액션 스페이스 | 10행, **±20° 제한**, 최고 2.60 m/s |
| 학습 | 15분 (`D-speedup`에서 Clone) |
| 하이퍼파라미터 | PPO · Batch 64 · **Epochs 3** · **Discount 0.995** · LR 0.0003 · Entropy 0.01 |

기본값에서 **실제로 바꾼 것은 Epochs(10→3)와 Discount(0.99→0.995) 둘뿐이다.**
근거는 [hyperparameters.md](docs/hyperparameters.md).

```
액션 스페이스
 -20/1.30  -14/1.60   -8/2.00   -3/2.30    0/2.60
   3/2.30    8/2.00   14/1.60   20/1.30    0/2.00
```

**조향각이 커질수록 속도가 내려간다.** 물리 계산을 그대로 따른 배치다.

### 모델 계보

```
D  (중앙선 + 워블 억제)
└─ D-speedup            속도 상향. 실차에서 유일하게 안정적으로 움직였다
   └─ D-speedup-clone   20도 구간 감속 + 직진 구간 증속 파인튜닝  <- 최종본
      └─ (이후 각도·속도·좌표 추가 시도는 모두 악화되어 폐기)
```

## 왜 좌표를 버렸는가

### 시뮬레이터에서는 가설이 맞았다

| 레인 | 보상이 주는 정보 | 평균 | 탈선 | 편차 |
| :--- | :--- | ---: | ---: | ---: |
| **E** | 좌표 + 목표속도 | **7.473** | 0 | **0.086** |
| **C** | 곡률 기반 속도 | 9.283 | 0 | 0.408 |
| A | 중앙선 | 9.501 | 1 | 1.003 |
| D | 중앙선 + 워블 억제 | 9.698 | 1 | 1.104 |

**정보량이 많은 보상이 그대로 순위였다. E > C > A > D.**

### 실차에서 뒤집혔다

| 레인 | 결과 |
| :--- | :--- |
| B · E (좌표) | **트랙 반대쪽으로 계속 이탈** |
| **D (중앙선 + 워블 억제)** | **유일하게 안정적으로 완주 → 채택** |

### 원인 1 — 여유폭이 레이턴시를 못 버텼다

| 라인 | 흰선까지 여유 | 지연 100ms · 2.0m/s = 0.20m 밀림 |
| :--- | ---: | :--- |
| 최적 경로 | **0.180 m** | **111% 소모 — 초과** |
| 센터라인 | 0.439 m | 46% 소모 |

0.180 m는 **지연이 없는 시뮬레이터에서는** 충분한 값이었다.

### 원인 2 — 보상이 요구한 과제가 달랐다 (더 근본적)

| | 센터라인 | 좌표 |
| :--- | :--- | :--- |
| 정책이 풀어야 할 문제 | **차선을 화면 중앙에 놓기** | **트랙의 몇 번째 지점인지 알아내고 인쪽에 붙기** |
| 필요한 능력 | 국소 반응 | **전역 자기위치 추정** |
| 실차 전이 | 된다 | **안 된다** |

좌표 보상은 자기위치 추정을 강요하고, 정책은 그것을 **시뮬 고유의 배경·텍스처를
외워서** 해결한다. 실제 트랙에는 그 단서가 없다.

> **"보상에 정보를 많이 주면 좋다"가 시뮬에서는 맞고 실차에서는 틀린 이유다.
> 정보가 많은 보상은 전이되지 않는 능력을 요구했다.**

## 조향각을 키우면 코너가 느려진다

`R = 축간거리 / tan(조향각)`, 한계속도 `sqrt(0.6g · R)` (축간거리 0.165 m)

| 조향각 | 회전반경 | 한계속도 |
| ---: | ---: | ---: |
| 14도 | 0.662 m | 1.97 m/s |
| **20도** | **0.453 m** | **1.63 m/s** |
| 30도 | 0.286 m | **1.30 m/s** |

**각도를 키우면 회전반경이 작아져 한계속도가 내려간다.** 실차에서 25·30도를
시도했을 때 **바퀴가 헛돈** 것이 이것이다. 게다가 큰 조향 액션이 존재하는 것만으로
정책이 그것을 써서 **직진에서 좌우로 왔다갔다하며 잃는 시간이 더 컸다.**

**20도가 코너를 가장 잘 소화하는 지점이었고, 그 각도에서 감속하고 직진에서
증속하는 것이 정답이었다.**

## 방향은 기본값을 쓰면 안 되는 항목이었다

A to Z Speedway는 **양방향 모두 선택 가능**하다. 처음에 기본값(시계)을 확인 없이
썼다. 같은 모델을 방향만 바꿔 평가한 결과:

| 모델 | 시계 | 반시계 | 배율 |
| :--- | ---: | ---: | ---: |
| A-v1 | 8.704 | **39.527** | 4.5배 |
| D-v1 | 8.967 | **42.291** | 4.7배 |
| C-v1 | 8.698 | **20.994** | 2.4배 |

정책은 `카메라 픽셀 -> 행동` 함수다. 방향을 뒤집으면 학습한 적 없는 입력이 되고,
코너 순서가 역순이 되며, 선회 방향이 반대가 된다. **거의 전면 실패한다.**

## 병목이 학습 시간일 때의 전략

학습 1회에 **약 2시간 30분** (훈련 1시간 + 검증·실행 1시간 + 기타).
**순차 파인튜닝은 성립하지 않는다.** 하루 3~4번이 한계다.

### 하나 — 가설을 벌려 병렬 검증

| 레인 | 가설 | 방식 |
| :--- | :--- | :--- |
| B | 최적 궤적이 랩타임을 만든다 | 좌표 |
| C | 감가속 타이밍이 랩타임을 만든다 | 곡률 |
| E | 위치와 속도를 함께 주면 가장 빠르다 | 좌표 + 속도 |
| A | 단순·안정이 이긴다 | 중앙선 |
| D | 실차 일관성이 이긴다 | 중앙선 + 워블 억제 |

**좌표 3개 + 중앙선 2개.** 전부 좌표로 갔으면 실차에서 아무것도 못 건졌다.

### 둘 — 학습 밖의 손잡이

| 손잡이 | 1회 반복 비용 |
| :--- | :--- |
| 재학습 | 약 2시간 30분 |
| **스로틀 배율** | **수십 초** |
| 출발 위치 | 수십 초 |
| 구간별 수동 제어 | 수십 초 |

**같은 모델에서 배율을 2% 단위로 올려 이탈하지 않는 최대선을 찾았다.**

| 배율 | 결과 |
| :--- | :--- |
| 60~61% | 완전 주행 |
| 62% | 이탈 없으나 살짝 걸침 |
| 63% | 코너 안정권 |
| **64%** | **이탈 1회** |

**장소를 옮기니 척도가 이동했다** — 이전 장소의 75%가 새 장소의 65%였다.
노면 마찰과 배터리가 바뀌면 배율-속도 관계가 달라져 **측정값을 재사용할 수 없다.**

최종 주행은 배율을 하나로 묶지 않았다.

```
출발 75%  ->  코너 진입 전 62%  ->  코너 통과  ->  즉시 75% 복귀
```

**가장 느린 구간이 랩 전체의 상한을 결정하는 문제를 구간 분할로 풀었다.**
출발 위치도 카메라 기준 가장 뒤로 옮겨 가속 거리를 확보했다.

## 계산해서 얻은 것

log-guru의 A to Z 센터라인 웨이포인트 110점에 **곡률 균등화(K1999) 1500회**를
적용해 최적 궤적을 직접 계산했다.

| 지표 | 센터라인 | 계산된 라인 |
| :--- | ---: | ---: |
| 길이 | 16.635 m | **15.409 m** (-7.4%) |
| 최소 코너 반경 | 0.61 m | **0.79 m** (+30%) |
| 흰선까지 여유 | 0.439 m | 0.180 m |

목표속도는 2단계로 계산했다. ① 각 점의 코너 한계속도 `sqrt(횡가속도 한계 / 곡률)`
② 그 상한을 따라 앞뒤로 가감속 전파.

**계산 자체는 맞았다. 시뮬에서 7.473초로 증명됐다. 문제는 마지막 열이었다** —
여유 0.180 m가 실차 레이턴시를 버티지 못했다.

## 콘솔 조작 함정

1. **값 입력 후 반드시 Tab.** 안 누르면 액션 스페이스 값이 전부 되돌아간다
2. **Discrete 선택 후 `Advanced configuration` 토글 ON.** 안 켜면 자동 격자가
   **큰 조향각에 최고 속도를 붙인 채로** 학습된다 (실차 스핀의 직행 코스)
3. **granularity는 초기 행 개수, Maximum은 상한**으로 계속 작동한다.
   Maximum speed를 먼저 올려야 행에 그 값을 넣을 수 있다 (기본값 1)
   - 조향 5 × 속도 2 = 10행, 조향 7 × 속도 2 = 14행. **12행은 만들 수 없다**
4. **보상 함수는 PEP8 통과 필수** — `def` 앞에 빈 줄 2개, 한 줄 79자 이하
5. 트랙 검색은 `A to Z`로. **16.64 m · 107 cm** 표시를 확인
6. `Actions -> Clone`은 학습이 끝난 뒤에만 활성화된다
7. 실차용 파일은 `Actions -> Download physical car model`
8. **JS로 라디오·체크박스를 클릭하면 안 된다.** DOM만 바뀌고 React 상태가
   갱신되지 않아 리렌더 시 선택이 되돌아간다. 실제 클릭만 쓴다

## 다시 한다면

1. **방향을 가장 먼저 확인한다.** 기본값을 믿지 않는다. 4배 차이가 난다
2. **실차 검증을 최대한 앞으로 당긴다.** 시뮬 순위는 실차 순위가 아니다
3. **보상은 전이되는 단서만 쓴다.** 절대 좌표보다 상대량이 강하다
4. **여유폭을 지연 기준으로 설계한다.** `지연 × 속도`가 최소 여유폭이다
5. **가설을 벌려 병렬 검증한다.** 병목이 학습 시간이면 순차 개선은 불가능하다
6. **학습 밖의 손잡이를 찾는다.** 배율·출발위치·구간제어는 초 단위로 반복된다
7. **검증된 모델을 함부로 이기려 하지 않는다.** 후속 개선 시도는 대부분 악화됐다
