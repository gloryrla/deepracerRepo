# 하이퍼파라미터를 그렇게 정한 이유

> 최종 모델 `D-speedup-clone` 기준. **기본값에서 실제로 바꾼 것은 2개뿐이다.**

---

## 최종 설정

| 항목 | 기본값 | 우리 값 | 바꿨나 |
| :--- | :--- | :--- | :--- |
| Gradient descent batch size | 64 | 64 | — |
| **Number of epochs** | **10** | **3** | **변경** |
| Learning rate | 0.0003 | 0.0003 | — (Clone은 0.0001) |
| Entropy | 0.01 | 0.01 | — (Clone은 0.005) |
| **Discount factor** | **0.99** | **0.995** | **변경** |
| Loss type | Huber | Huber | — |
| Exploration type | categorical | categorical | — |
| Experience episodes between updates | 20 | 20 | — |

**의도적으로 2개만 바꿨다.** 학습 1회에 2시간 30분이 드는 환경에서 여러 값을
동시에 바꾸면 어느 것이 효과를 냈는지 알 수 없다. 실패해도 원인을 못 찾고
2시간 30분을 버린다.

---

## Number of epochs: 10 → 3 (변경)

### 무엇인가

PPO는 경험을 한 번 모은 뒤 **그 같은 데이터로 몇 번 반복해서 가중치를
업데이트**한다. epochs가 그 횟수다.

### 왜 낮췄나

**같은 데이터를 많이 재사용하면 정책이 그 데이터를 만든 정책에서 너무 멀리
가버린다.** PPO의 클리핑이 이걸 일부 막아주지만 완전히는 못 막는다.

우리 설정은 업데이트당 경험이 **20 에피소드**뿐이다. 이 좁은 데이터를 10번
반복하면 정책이 **최근 몇 바퀴의 우연한 궤적에 과적합**된다. 증상은 학습 곡선이
올라가다 갑자기 무너지는 것이다.

**그리고 여기가 결정적이다. 60분짜리 학습이 중간에 붕괴하면 60분을 통째로
날린다.** 표본 효율보다 **안정성**이 훨씬 값비쌌다. epochs 3은 같은 데이터를
덜 짜내는 대신 무너지지 않는다.

> 요약: epochs가 높으면 **빨리 배우지만 무너질 위험**이 크다.
> 재시도 비용이 2시간 30분이면 그 도박은 기대값이 마이너스다.

---

## Discount factor: 0.99 → 0.995 (변경)

### 무엇인가

미래 보상을 얼마나 값있게 볼지 정한다. **유효 시야가 `1/(1-γ)` 스텝**이다.

| γ | 유효 시야 | 시간 (15 Hz) |
| :--- | ---: | ---: |
| 0.99 | 100 스텝 | 6.7초 |
| **0.995** | **200 스텝** | **13.3초** |
| 0.999 | 1000 스텝 | 66.7초 |

### 왜 올렸나

**랩 하나가 몇 스텝인지 계산해보면 0.99로는 부족하다.**

| 평균 속도 | 랩타임 | 스텝 수 |
| :--- | ---: | ---: |
| 2.6 m/s | 6.40초 | 96 |
| 2.0 m/s | 8.32초 | 125 |
| 1.6 m/s | 10.40초 | **156** |
| 1.3 m/s | 12.80초 | **192** |

**γ=0.99의 시야는 100스텝이다. 학습 초기의 느린 주행(156~192스텝)은 랩이
시야보다 길다.** 즉 에이전트가 **한 바퀴를 온전히 하나의 결과로 볼 수 없다.**

이게 실제로 문제가 되는 지점이 있다. 우리는 **"다음 코너를 위해 지금 감속해야
한다"**를 학습시키려 했다. 그건 지금의 행동과 몇 초 뒤의 결과를 연결하는
**신용 배분(credit assignment)** 문제다. 시야가 랩보다 짧으면 그 연결이 끊긴다.

γ=0.995는 200스텝 = 13.3초로 **어떤 속도의 랩도 온전히 담는다.**

### 왜 0.999로 더 올리지 않았나

시야가 1000스텝(66.7초)이면 랩 5~10개를 뭉쳐서 본다. **가치 추정의 분산이
커져 수렴이 느려지고 불안정해진다.** 필요한 것은 "랩 하나를 담는 시야"이고,
그보다 크면 노이즈만 늘어난다.

> 요약: **γ는 "랩 하나가 시야에 들어오는가"로 정했다.** 0.99는 부족하고
> 0.999는 과하다.

## 나머지를 기본값으로 둔 이유

### Batch size 64 (유지)

배치가 작으면 업데이트가 자주 일어나 **초반에 빨리 움직인다.** 60분 안에
쓸만한 정책을 만들어야 하는 상황에서 맞는 선택이다. 배치를 키우면 기울기가
정확해지지만 업데이트 횟수가 줄어 60분 안에 충분히 학습하지 못한다.

### Loss type: Huber (유지)

우리 보상에는 **절벽이 있다.** 이탈하면 1e-3으로 떨어진다.

MSE(제곱 오차)를 쓰면 그 한 번의 큰 오차가 **기울기를 지배**한다. Huber는
큰 오차의 영향을 선형으로 눌러서 **한 번의 파국적 에피소드가 학습 전체를
흔드는 것을 막는다.** 이탈이 흔한 초기 학습에서 특히 중요하다.

### Exploration type: categorical (유지)

**이산 액션 스페이스에서는 이것이 맞는 선택이다.** 우리는 10행 표로 액션을
직접 정의했으므로 각 액션의 확률을 다루는 categorical이 자연스럽다.
(연속 액션이면 Gaussian을 쓴다.)

### Experience episodes between updates: 20 (유지)

업데이트 한 번에 쓸 경험량이다. 20 에피소드면 대략 **200초 분량의 주행**이다.
너무 적으면 기울기가 노이즈고, 너무 많으면 업데이트가 드물어 60분 안에
충분히 못 배운다.

### Learning rate 0.0003 / Entropy 0.01 (신규 학습) 

기본값을 그대로 썼다. 새 정책을 처음부터 만들 때는 **탐색이 필요하고**
가중치를 크게 움직여야 한다.

## Clone(파인튜닝)에서 바꾼 것

`D-speedup -> D-speedup-clone`처럼 **이미 잘 되는 모델을 다듬을 때**는 두 값을
낮춘다.

| 항목 | 신규 학습 | **Clone** | 이유 |
| :--- | :--- | :--- | :--- |
| Learning rate | 0.0003 | **0.0001** | 이미 학습된 가중치를 크게 흔들면 잘 되던 것이 깨진다 |
| Entropy | 0.01 | **0.005** | 탐색이 아니라 **정제** 단계다. 높으면 정책이 알면서도 가끔 엉뚱한 액션을 고른다 |
| 학습 시간 | 45~60분 | **15분** | 기초는 이미 있으므로 짧게 |

**최종 모델은 15분 Clone이다.** 0에서 시작한 게 아니라 실차에서 검증된
`D-speedup`을 물려받아 20도 구간 감속과 직진 증속만 다듬었다.

> 주의: **Clone에서 액션 개수를 바꾸면 이 이점이 크게 줄어든다.** 정책 신경망의
> 출력층 크기가 달라져 학습된 가중치의 상당 부분을 다시 배워야 한다.
> 10행에서 14행으로 늘리는 것은 사실상 신규 학습에 가깝다.

## Maximum time을 짧게 유지한 이유

| 학습 시간 | 판단 |
| :--- | :--- |
| 15~60분 | **채택 범위** |
| 3시간 이상 | 피했다 |

오래 돌리면 **시뮬레이터의 픽셀(배경·텍스처·조명)에 과적합**된다. 시뮬 기록은
계속 좋아지는데 실차에서는 오히려 무너진다.

이번 대회의 핵심 교훈이 정확히 이 방향이었다. 시뮬에서 가장 정교하게 최적화된
모델(E-v1, 60분, 7.473초, 편차 0.086초)이 실차에서 가장 먼저 탈락했다.
**시뮬 성능을 더 짜내는 것이 실차 성능을 깎을 수 있다.**

그래서 "과적합이 생기지 않는 선에서 여러 시간대에 여러 모델을 돌리는" 방식을
택했다. 자세한 내용은 [lessons_learned.md](lessons_learned.md).

## 한 줄 정리

| 값 | 왜 |
| :--- | :--- |
| epochs **3** | 재시도 비용이 2시간 30분이라 **안정성 > 표본 효율** |
| discount **0.995** | 유효 시야 200스텝이 **랩 하나(96~192스텝)를 담는다** |
| Huber | 보상에 이탈 절벽이 있어 **한 번의 파국이 기울기를 지배하는 것**을 막는다 |
| batch 64 | 60분 안에 **업데이트 횟수**를 확보 |
| Clone은 LR 0.0001 · Entropy 0.005 | **정제 단계**이므로 크게 흔들지 않는다 |
| 학습 15~60분 | 3시간 넘기면 **시뮬 픽셀에 과적합**된다 |
