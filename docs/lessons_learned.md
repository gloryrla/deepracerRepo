# 배운 것 — 시뮬레이터에서 이긴 가설이 실차에서 진 이유

> 이 문서가 이번 대회의 핵심 산출물이다. 기록보다 **왜 그렇게 됐는지**가 남는다.

---

## 1. 순위가 뒤집혔다

### 시뮬레이터

| 레인 | 보상이 주는 정보 | 평균 | 탈선 | 편차 |
| :--- | :--- | ---: | ---: | ---: |
| **E** | 좌표 + 목표속도 | **7.473** | 0 | **0.086** |
| **C** | 곡률 기반 속도 | 9.283 | 0 | 0.408 |
| A | 중앙선 | 9.501 | 1 | 1.003 |
| D | 중앙선 + 워블 억제 | 9.698 | 1 | 1.104 |

**정보량이 많은 보상이 그대로 순위였다. E > C > A > D.** 가설이 맞았다.

### 실차

| 레인 | 결과 |
| :--- | :--- |
| B · E (좌표 기반) | **트랙 반대쪽으로 계속 이탈** |
| **D (중앙선 + 워블 억제)** | **유일하게 안정적으로 완주 → 최종 채택** |

**시뮬 1위가 실차 탈락, 시뮬 최하위가 실차 우승.** 완전히 역전됐다.

---

## 2. 학습 부족이 아니었다

가장 먼저 의심한 것은 학습 시간이었다. **아니었다.**

E-v1은 **60분 학습, 시뮬 7.473초, 탈선 0회, 편차 0.086초**다.
미수렴이면 시뮬에서 먼저 드러난다. 시뮬이 완벽했으므로 원인은 학습이 아니라
**시뮬-실차 격차**다.

---

## 3. 원인 하나 — 여유폭이 카메라 레이턴시를 못 버틴다

카메라 지연 동안 차는 계속 굴러간다. 그만큼 늦게 반응한다.

| 지연 | 2.0 m/s | 2.6 m/s |
| :--- | ---: | ---: |
| 100 ms | 0.20 m | 0.26 m |
| 150 ms | 0.30 m | 0.39 m |

두 라인의 여유폭과 비교하면:

| 라인 | 흰선까지 여유 | 100 ms · 2.0 m/s |
| :--- | ---: | :--- |
| 최적 경로 (B·E) | **0.180 m** | **111% 소모 — 초과** |
| 센터라인 (A·D) | 0.439 m | 46% 소모 |

**지연 100 ms와 2.0 m/s만 되어도 최적 경로의 여유가 전부 사라진다.**

0.180 m는 시뮬레이터에서는 충분한 값이었다. 시뮬에는 지연이 없기 때문이다.
**우리는 지연이 없는 세계에 맞춰 여유폭을 설계했다.** 그게 실수였다.

---

## 4. 더 근본적인 원인 — 보상이 요구한 과제 자체가 달랐다

| | 센터라인 (A·D) | 좌표 (B·E) |
| :--- | :--- | :--- |
| 보상이 쓰는 값 | `distance_from_center` | 절대 좌표 `x, y` |
| 정책이 풀어야 할 문제 | **차선을 화면 중앙에 놓기** | **내가 트랙의 몇 번째 지점인지 알아내고 거기서 인쪽에 붙기** |
| 필요한 능력 | 국소 반응 | **전역 자기위치 추정** |
| 좌우 대칭성 | 대칭 | 비대칭 |

좌표 보상은 정책에게 **자기위치 추정**이라는 훨씬 어려운 지각 문제를 강요한다.
그리고 정책이 그것을 푸는 수단은 카메라 픽셀뿐이므로, 시뮬레이터의 배경·텍스처
같은 **시뮬 고유 단서를 외워서** 해결한다. 실제 트랙에는 그 단서가 없다.

센터라인이 요구하는 "차선 경계가 화면 어디 있나"는 **실차에도 그대로 존재하는
단서**다. 그래서 전이된다.

> **"보상에 정보를 많이 주면 좋다"가 시뮬에서는 맞고 실차에서는 틀린 이유가
> 이것이다. 정보가 많은 보상은 전이되지 않는 능력을 요구했다.**

이건 좌표를 더 정확하게 계산해서 해결되는 문제가 아니다. **접근 자체의 성질**이다.

### "왜 하필 반대쪽으로" 이탈했는가

무작위가 아니라 한쪽으로 계속 나갔다는 것이 진단의 단서다. 두 기전이 있다.

1. **코너에서 늦게 꺾어 바깥으로 밀림.** 최적 경로는 코너 인쪽에 붙는 라인이다.
   지연으로 턴인이 늦으면 인쪽을 노리다 **바깥으로** 밀려난다 — 겨냥한 쪽의 반대편
2. **방향 불일치로 인·아웃 거울반전.** 시계로 학습한 라인을 반시계로 달리면
   학습한 "인쪽"이 지금은 "아웃쪽"이다

구분법: 코너에서만 바깥으로 밀리면 1번, 직선에서도 한쪽으로 치우치면 2번.

## 5. 방향 불일치의 대가 — 별도로 확정된 사실

A to Z Speedway는 **양방향 모두 선택 가능**하다. 우리는 처음에 기본값(시계)을
확인 없이 썼다. 같은 모델을 방향만 바꿔 평가한 결과:

| 모델 | 시계 최고랩 | 반시계 최고랩 | 배율 |
| :--- | ---: | ---: | ---: |
| A-v1 | 8.704 | **39.527** | 4.5배 |
| D-v1 | 8.967 | **42.291** | 4.7배 |
| C-v1 | 8.698 | **20.994** | 2.4배 |

정책은 `카메라 픽셀 -> 행동` 함수다. 방향을 뒤집으면 이미지 분포가 학습 밖이 되고,
코너 순서가 역순이 되며, 선회 방향이 반대가 된다. **성능이 조금 나빠지는 게
아니라 거의 전면 실패한다.**

**교훈: 방향은 "기본값을 쓰는" 항목이 아니다. 가장 먼저 확인해야 하는 항목이다.**
최종 모델은 **Counterclockwise**로 학습됐다.

## 6. 조향각을 키우는 것은 코너 속도를 올려주지 않는다

코너 이탈을 막으려면 조향 권한을 늘려야 한다고 생각했다. 틀렸다.

자전거 모델로 `R = 축간거리 / tan(조향각)`, 한계속도 `sqrt(0.6g · R)`:

| 조향각 | 회전반경 | 한계속도 |
| ---: | ---: | ---: |
| 14도 | 0.662 m | 1.97 m/s |
| **20도** | **0.453 m** | **1.63 m/s** |
| 30도 | 0.286 m | 1.30 m/s |

**조향각을 키우면 회전반경이 작아지고 한계속도는 오히려 내려간다.**
30도는 1.30 m/s를 넘으면 어떻게 꺾어도 밀려나간다. 실차에서 관측된
"바퀴가 헛돈다"가 정확히 이것이다.

부작용도 있었다. **큰 조향 액션이 존재하는 것만으로 정책이 그것을 쓴다.**
직진 구간에서 좌우로 왔다갔다하며 잃는 시간이 코너에서 얻는 것보다 컸다.

**결론: 20도로 제한하고, 그 각도에서는 속도를 낮추고 직진에서 올린다.**

## 7. 병목이 학습 시간이면, 전략은 병렬화와 "학습 밖의 손잡이"다

학습 1회에 약 2시간 30분이 들었다. **파인튜닝을 순차로 반복하는 방식은 성립하지
않는다.** 하루에 3~4번밖에 못 돈다.

그래서 두 가지를 했다.

**하나. 처음에 가설을 최대한 벌려놓고 병렬로 검증했다.** 5개 레인에 서로 다른
가설을 걸었다. 좌표 기반 3개(B·C·E)와 중앙선 기반 2개(A·D)다.
**전부 좌표로 갔으면 실차에서 아무것도 못 건졌다.** 베팅 분산이 결과를 구했다.

**둘. 모델을 고정한 뒤 학습 밖의 손잡이를 돌렸다.**

| 손잡이 | 1회 반복 비용 |
| :--- | :--- |
| 재학습 | 약 2시간 30분 |
| **스로틀 배율** | **수십 초** |
| 출발 위치 | 수십 초 |
| 구간별 수동 제어 | 수십 초 |

**같은 모델에서 배율을 2% 단위로 올려가며 이탈하지 않는 최대선을 찾는 것**이
남은 시간에 성적을 올리는 가장 효율적인 수단이었다. 자세한 기록은
[physical_tuning_log.md](physical_tuning_log.md).

## 8. 강화학습에서 놓치기 쉬운 것 — 느린 것이 이득일 수 있다

보상은 **스텝마다 더해진다(15 Hz).** 느리게 달리면 스텝 수가 늘어난다.

| 속도 | 랩타임 | 스텝 수 |
| :--- | ---: | ---: |
| 2.4 m/s | 6.93초 | 104 |
| 1.2 m/s | 13.86초 | **208** |

**스텝당 보상이 같으면 절반 속도로 기어가는 쪽이 총보상을 2배 받는다.**
아무 대책이 없으면 **미적거리는 것이 최적 정책**이 된다.

속도 항을 넣을 때 지수가 중요하다. 보상이 `v^p`이고 스텝 수가 `1/v`이므로
총보상은 `v^(p-1)`이다.

| 지수 | 총보상 | 효과 |
| :--- | :--- | :--- |
| p = 1.0 | `v^0` | **정확히 상쇄. 아무 효과 없음** |
| p = 1.5 | `v^0.5` | 빠른 쪽이 유리 |
| p = 2.0 | `v^1` | 너무 강해 코너 감속을 안 할 위험 |

**속도 항의 지수는 반드시 1보다 커야 한다.** 이걸 모르고 `v`에 비례하는 항을
넣으면 아무 일도 일어나지 않는다.

## 9. 요약 — 다시 한다면

1. **방향을 가장 먼저 확인한다.** 기본값을 믿지 않는다. 4배 차이가 난다
2. **실차 검증을 최대한 앞으로 당긴다.** 시뮬 순위는 실차 순위가 아니다
3. **보상은 전이되는 단서만 쓴다.** 절대 좌표보다 상대량이 강하다
4. **여유폭을 지연 기준으로 설계한다.** `지연 × 속도`가 최소 여유폭이다
5. **가설을 벌려 병렬로 검증한다.** 병목이 학습 시간이면 순차 개선은 불가능하다
6. **학습 밖의 손잡이를 찾는다.** 배율·출발위치·구간제어는 초 단위로 반복된다
7. **검증된 모델을 함부로 이기려 하지 않는다.** 후속 개선 시도는 대부분 악화됐다
