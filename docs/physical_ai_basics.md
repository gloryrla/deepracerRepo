## GPT가 자동차를 운전하려면?

AI 모델은 결국 **입력을 받아 출력만** 한다.

| 분야 | 입력 | 모델 | 출력 |
| :--- | :--- | :--- | :--- |
| 이미지 AI | 이미지 | CNN | 분류·검출 |
| 텍스트 AI | 질문 | LLM | 답변 |
| **Physical AI** | **센서** | **정책** | **구동 명령** |

여기서 결정적인 차이가 하나 있다.

```
현실세계 -> 센서 -> 상태인식 -> AI모델 -> Actuator -> 현실세계
                                                        |
                                                        v
                                            다시 센서로 (feedback loop)
```

**여기서 끝내면 사고난다.** 출력이 현실을 바꾸고, 바뀐 현실이 다음 입력이 된다.
현실세계는 계속 변하기 때문에 **닫힌 루프**여야 한다.

이미지 분류는 한 번 틀려도 그 사진 하나가 틀리는 것으로 끝난다.
Physical AI는 **한 번의 잘못된 출력이 다음 입력을 망가뜨리고 누적된다.**
트랙 이탈이 정확히 그 현상이다.

### Feedback

> 센서와 구동장치를 통해 물리적 환경을 인지하고 행동한 뒤,
> **그 결과값을 다시 시스템에 반영해** 정밀성과 적응성을 높이는 핵심 작동 원리.

이번 대회에서 이 루프의 **지연(latency)**이 우리 전략을 뒤집었다.
자세한 내용은 [lessons_learned.md](lessons_learned.md).

## Physical AI의 구성

### 1. 센서 (Sensing)

| 센서 | 이번 대회 |
| :--- | :--- |
| 카메라 | **사용 (모노 1대)** |
| 라이다 | 미사용 |
| GPS | 미사용 |
| 초음파 | 미사용 |

**우리 차는 카메라 하나뿐이다.** 이것이 좌표 기반 접근이 실패한 근본 이유와
직결된다. "내가 트랙의 어디인가"를 카메라 픽셀만으로 추정해야 했다.
라이다나 GPS가 있었다면 좌표 방식이 성립했을 수 있다.

### 2. 판단 (Decision)

"오른쪽으로 기울면 왼쪽으로 기울이기"를 결정하는 방법.

| 방법 | 성격 |
| :--- | :--- |
| Rule based | 사람이 규칙을 직접 쓴다 |
| 머신러닝 | 데이터에서 규칙을 배운다 |
| 딥러닝 | 특징까지 스스로 찾는다 |
| **강화학습** | **시행착오로 보상을 최대화한다 ← 이번 대회** |

### 3. 행동 (Action)

| 구동장치 | 이번 대회 |
| :--- | :--- |
| Steering | **사용** |
| 모터 | **사용 (속도)** |
| 브레이크 | 간접 (속도 액션 감소) |
| 로봇 팔 | 해당 없음 |

## 강화학습 개념

### 왜 강화학습인가

지도학습은 **정답이 있어야** 한다. 그런데 "이 코너에서 조향 몇 도"의 정답을
사람이 라벨링할 수 없다. 대신 **결과(완주·랩타임)만 평가할 수 있다.**
그것이 강화학습이 맞는 문제 구조다.

### Markov Reward Process

현재 상태만으로 다음 상태와 보상이 결정된다는 가정(마르코프 성질).

**이번 대회에서 이 가정이 깨진 지점이 있었다.** 보상 함수는 이전 스텝을
기억하지 못한다. 그래서 "조향을 얼마나 급하게 바꿨는가"를 벌주려면
직전 조향각을 모듈 전역에 따로 저장해야 했다.

```python
PREV = {'steer': 0.0}   # 마르코프 가정을 우회하는 장치
...
rate = abs(steer - PREV['steer'])
```

워블(좌우 떨림)은 **한 스텝만 봐서는 판별할 수 없는 현상**이기 때문이다.

### 알고리즘

| 알고리즘 | 성격 |
| :--- | :--- |
| **PPO** | On-policy. 안정적이고 튜닝이 쉽다. **이번 대회 전 모델이 PPO** |
| SAC | Off-policy. 샘플 효율이 높지만 연속 액션 위주 |

우리는 이산 액션(액션 스페이스 표)을 썼으므로 PPO가 자연스러웠다.

### 몬테카를로 방법

에피소드를 끝까지 굴려보고 실제 받은 보상 합으로 가치를 추정하는 방식.
DeepRacer의 학습이 "랩을 계속 돌려보는" 형태인 이유다.

**여기서 실무적으로 중요한 함정이 나온다.** 보상은 스텝마다 더해지므로
**느리게 달리면 스텝이 늘어나 총보상이 커진다.**

| 속도 | 랩타임 | 스텝 수 |
| :--- | ---: | ---: |
| 2.4 m/s | 6.93초 | 104 |
| 1.2 m/s | 13.86초 | **208** |

대책이 없으면 **미적거리는 것이 최적 정책**이 된다.
자세한 해법은 [lessons_learned.md](lessons_learned.md) 8절.

### LLM의 학습 과정과의 대비

| 단계 | LLM |
| :--- | :--- |
| 비지도학습 | 대량 텍스트로 사전학습 |
| 지도학습 | 사람이 만든 좋은 답변으로 미세조정 (SFT) |
| **강화학습** | **사람 선호로 정책을 다듬음 (RLHF)** |

LLM도 마지막에 강화학습을 쓴다. **"정답을 못 쓰지만 좋은지 나쁜지는 말할 수
있다"는 구조가 같다.** DeepRacer는 그 평가자가 사람이 아니라 시뮬레이터다.

## 대회 운영 확인 사항

학습 전에 물어봐야 했던 것들. **답에 따라 전략이 완전히 달라진다.**

| 질문 | 답 | 영향 |
| :--- | :--- | :--- |
| 병렬 학습 가능? | **가능** (오래 걸릴 수 있음) | 5개 레인 동시 검증의 근거 |
| 1·2차 스로틀·모델 조절 허용? | **모델·스로틀 모두 조절 가능** | 학습 밖 손잡이 전략의 근거 |
| 시간 기준: 한 바퀴 vs 합산? | (확인 필요) | 공격 수위 결정 |
| 주행 방향? | **반시계** | **4배 차이. 가장 중요했다** |

**밤새 돌리는 것도 가능했다.** 학습 1회 2시간 30분이라는 병목을 감안하면
야간 시간을 쓰는 것 자체가 자원이었다.
